# Årsregnskap til Regnskapsregisteret (RR-0002, Altinn 3)

Integration specification and design notes for Myntos's annual accounts
(`myntos.aarsregnskap`, `myntos.integrations.aarsregnskap`,
`myntos.api.v1.aarsregnskap`, `frontend/src/pages/aarsregnskap.astro`).

## Live Altinn 3 Specification (Verified 2026-11-28)

- **Altinn 3 App:** `brg/aarsregnskap-vanlig-202406`
  - Production: `https://brg.apps.altinn.no/brg/aarsregnskap-vanlig-202406`
  - TT02 test: `https://brg.apps.tt02.altinn.no/brg/aarsregnskap-vanlig-202406`
  - Configured via `ALTINN_AARSREGNSKAP_APP_URL` (`Settings.altinn_aarsregnskap_app_url`).
- **Resource Registry ID:** `app_brg_aarsregnskap-vanlig-202406` (`delegable: true`
  in both production and TT02). Declared in
  `myntos.integrations.altinn.systemregister.SYSTEM_RESOURCES` and requested by
  default alongside `ske-innrapportering-aksjonaerregisteroppgave`.
- **Scopes:** `altinn:instances.read` and `altinn:instances.write` (both
  Maskinporten systembruker and ID-porten).
- **XML Data Types (`application/xml`, NOT `text/xml`):**
  - `Hovedskjema` (`RR-0002`, `dataFormatId="1266"`, `dataFormatVersion="51820"`,
    auto-created at instantiation, replaced via `PUT .../data/{id}`).
  - `Underskjema` (`RR-0002-U`, `dataFormatId="758"`, `dataFormatVersion="51980"`,
    auto-created at instantiation, replaced via `PUT .../data/{id}`).
  - `Vedlegg` (optional PDF attachments, max 30 MB, max 20 files).
  - `ref-data-as-pdf` and `signature` (generated by the app upon signing and
    archived in `DocumentStorage` for five-year retention under bokføringsloven § 13).

## Two-Step Legal Workflow

1. **Prepare & lock (`Utfylling` -> `Signering`):**
   - `POST /instances` (`organisationNumber`)
   - `PUT /instances/{party}/{guid}/data/{hovedskjema_id}` (`application/xml`)
   - `PUT /instances/{party}/{guid}/data/{underskjema_id}` (`application/xml`)
   - Optional `POST /instances/{party}/{guid}/data?dataType=Vedlegg` (`application/pdf`)
   - `GET /instances/{party}/{guid}/validate`
   - `PUT /instances/{party}/{guid}/process/next` with `{"action": "confirm"}`
   - Allowed via **Altinn 3 systembruker** (`POST /aarsregnskap/klargjor`) or
     **ID-porten** (`POST /aarsregnskap/send`).
2. **Sign & auto-submit (`Signering` -> `EndEvent_1`):**
   - `PUT /instances/{party}/{guid}/process/next` with `{"action": "sign"}`
   - **Must** use a person's ID-porten-derived Altinn token (never systembruker),
     because signing attaches a fødselsnummer and submits directly to
     Regnskapsregisteret (`POST /aarsregnskap/innsendinger/{id}/signer` or
     `POST /aarsregnskap/send` with `signer_direkte: true`).
   - Board members may alternatively open `altinn_portal_url` in Altinn and
     sign there, then poll `POST /aarsregnskap/innsendinger/{id}/status` to
     archive `ref-data-as-pdf`.

## Official XSD Validation

All four official XSD files from `brreg/docs` are vendored verbatim in
`backend/tests/fixtures/aarsregnskap/` (both current live schemas and the
stricter January 2027 schemas). `backend/tests/test_aarsregnskap_xml.py`
validates every generated Hovedskjema and Underskjema scenario against both
versions using `lxml.etree.XMLSchema`.

## Privacy and Failure Persistence

- **Public disclosure:** Everything submitted to Regnskapsregisteret (including
  `Vedlegg` PDFs) becomes public. Generated PDFs never include fødselsnummer,
  personal home addresses, or IP addresses.
- **Partial-failure persistence:** Remote failures return HTTP 502 via
  `JSONResponse` instead of raising so the `feilet` row carrying any live
  `altinn_instance_id` is committed rather than rolled back.
